## 2. Plugin system
Target: match mypy's `Plugin` protocol surface so existing plugins port with minimal friction, but Rust trait-based and statically registered (no dynamic dispatch over FFI for v1).

### 2.1 New crate `crates/rustypy_plugin`
Define the trait, mirroring mypy hooks (`mypy/plugin.py` verified list):
```rust
pub trait Plugin: Send + Sync {
    fn name(&self) -> &str;
    fn get_function_hook(&self, fullname: &QName) -> Option<fn(&FunctionContext) -> Type>;
    fn get_method_hook(&self, fullname: &QName) -> Option<fn(&MethodContext) -> Type>;
    fn get_function_signature_hook(&self, fullname: &QName) -> Option<fn(&FunctionSigContext) -> FunctionLike>;
    fn get_method_signature_hook(&self, fullname: &QName) -> Option<fn(&MethodSigContext) -> FunctionLike>;
    fn get_attribute_hook(&self, fullname: &QName) -> Option<fn(&AttributeContext) -> Type>;
    fn get_class_attribute_hook(&self, fullname: &QName) -> Option<fn(&AttributeContext) -> Type>;
    fn get_class_decorator_hook(&self, fullname: &QName) -> Option<fn(&mut ClassDefContext)>;
    fn get_class_decorator_hook_2(&self, fullname: &QName) -> Option<fn(&mut ClassDefContext) -> bool>;
    fn get_metaclass_hook(&self, fullname: &QName) -> Option<fn(&mut ClassDefContext)>;
    fn get_base_class_hook(&self, fullname: &QName) -> Option<fn(&mut ClassDefContext)>;
    fn get_customize_class_mro_hook(&self, fullname: &QName) -> Option<fn(&mut ClassDefContext)>;
    fn get_dynamic_class_hook(&self, fullname: &QName) -> Option<fn(&mut DynamicClassDefContext)>;
    fn get_type_analyze_hook(&self, fullname: &QName) -> Option<fn(&AnalyzeTypeContext) -> Type>;
    fn get_additional_deps(&self, file: &ModulePath) -> Vec<(usize, ModuleName, usize)>;
    fn report_config_data(&self) -> ConfigData;  // cache fingerprint
}
```
Context structs (`FunctionContext`, `MethodContext`, `ClassDefContext`, etc.) wrap the existing pyrefly `BindingsBuilder`/`ClassDefBuilder` state. Two-pass class transform preserved: `class_decorator_hook` (placeholders OK) then `class_decorator_hook_2` (resolved; return `false` to request another pass), mirroring mypy.

## 3. Config bridge
Reuses pyrefly's existing `crates/pyrefly_config/src/migration/` (already imports mypy.ini/pyproject + pyrightconfig). Extends it to cover the gaps the analysis flagged.

### 3.1 mypy strict expansion (mypy 2.x, 13 flags)
`strict = true` enables exactly: `disallow_any_generics`, `disallow_subclassing_any`, `disallow_untyped_calls`, `disallow_untyped_defs`, `disallow_incomplete_defs`, `check_untyped_defs`, `disallow_untyped_decorators`, `warn_redundant_casts`, `warn_unused_ignores`, `warn_return_any`, `implicit_reexport = False` (no_implicit_reexport), `strict_equality`, `extra_checks`. Map each to existing pyrefly error codes / config keys; add a `rustypy` preset `mypy-strict` that enables all 13.
- `no_implicit_optional` is NOT in strict (mypy 2.x default already False). Document this.

### 3.2 Missing mypy flags to implement
- `follow_imports = "silent"|"skip"|"error"|"normal"` per-module and global. Wire to pyrefly's module loader (`lib/module/finder.rs` + `lib/state/load.rs`): `silent` = parse but suppress errors, `skip` = don't parse, `error` = missing source is an error.
- `ignore_errors = true` per-module: gate the error collector (`lib/error/collector.rs`) by module path.
- `disallow_untyped_defs = true`: error code `untyped-def` for functions without full annotations. Implement as a binding-pass check in `lib/binding/binding.rs`.
- `-p PACKAGE` / `-m MODULE` CLI mode: resolve a dotted name to a source set via `module_name.rs` + finder. Add `rustypy check -p mypackage`.
- `--warn-unused-ignores`, `--warn-redundant-casts`, `--warn-return-any`: ensure codes exist and are wired (some already in pyrefly).
- Per-module overrides `[[tool.mypy.overrides]]` globbing: replicate mypy's three-tier precedence (concrete > unstructured last-wins > structured specificity) in `crates/pyrefly_config/src/module_wildcard.rs` + `Options.build_per_module_cache`-equivalent. `module` accepts string or array.
- `always_true` / `always_false` / `disable_error_code` / `enable_error_code` per-module (enabling overrides disabling at same scope).

### 3.3 Missing pyright surface
- `typeCheckingMode` presets `off`/`basic`/`standard`/`strict`: map to rustypy presets. `strict` = `mypy-strict` preset + pyright-specific extras.
- `--verifytypes PKG`: new subcommand `rustypy verifytypes PKG`. Walks public API (re-exported names per `no_implicit_reexport` rules), reports any symbol whose type is `Any`/`Unknown`/partial. Exit non-zero on incomplete. Reuse `lib/export/exports.rs` for the public-API walk.
- `reportGeneralTypeIssues` + all `report*` categories: map to rustypy error-code groups. Maintain a pyright-name -> rustypy-code table in `crates/pyrefly_config/src/migration/pyright.rs`.
- Separate `reportMissingImports` (module not found) from `reportMissingTypeStubs` (module found, no `py.typed`/stubs). pyrefly already distinguishes internally; expose as two codes. This is the ty gap we must NOT replicate.

### 3.4 Config file search order
`rustypy.toml` > `[tool.rustypy]` in `pyproject.toml` > `pyrefly.toml` (legacy) > `mypy.ini`/`[tool.mypy]` > `pyrightconfig.json` (auto-migrate). Migration is non-destructive: writes a `rustypy.toml` and prints a diff for review.

## 4. Bug fixes (every documented issue)

### 4.1 Star-import reexport in site-packages
**Where**: `pyrefly/lib/module/finder.rs` `find_third_party_stub` (lines ~94-156, 354-375) + `package_has_py_typed` gating in `crates/pyrefly_build/src/module_resolver.rs:231`.
**Root cause**: when a `py.typed` package's `__init__.py` uses `from ._impl import *` under `TYPE_CHECKING`, the export solver (`lib/export/exports.rs`) doesn't transitively pull names from the star-imported submodule when resolving third-party stubs, so `BaseModel`/`SecretStr` (pydantic) and `nx.Graph` (types-networkx) resolve to `object`.
**Fix**: in the export pass, when a `py.typed` third-party package is resolved, eagerly compute the transitive star-import closure and merge exported names. Add a conformance test with a synthetic `py.typed` package mimicking pydantic's `__init__.py` shape.
**Risk**: medium. Touches module resolution ordering. Mitigation: gated behind existing test suite + new regression tests.

### 4.2 typeshed-path namespace identity conflict
**Where**: `pyrefly/lib/module/finder.rs:462-466` (custom `typeshed_path` join) + class identity in `crates/pyrefly_types/src/class.rs` (`ClassInner` = `ClassDefIndex` + `QName` + `ModulePath`).
**Root cause**: `int` annotation resolves via custom typeshed path (file path A); literal `1` resolves via bundled `BundledTypeshed` (file path B). `Class` equality requires matching `ModulePath`, so `Literal[1]` is not assignable to `int`.
**Fix**: decouple class identity from the specific stub file path. Identity should be `(ClassDefIndex, QName)` canonicalized against the logical module (e.g. `builtins.int`), not the physical stub path. Add a `canonical_module` field to `ClassInner`; equality uses canonical module + def index. Update `Hash`/`PartialEq`/`Ord` impls on `Class`. Audit every `ClassType` construction site for path-sensitive equality.
**Risk**: high. This is the profound change. It touches the core type identity invariant. Mitigation: incremental rollout behind a config flag `rustypy.canonical-class-identity = true` (default false in v1, true after soak); full conformance suite + new regression tests for `Literal[1]` vs `int`, `NoneType` identity, cross-typeshed `isinstance` narrowing.

### 4.3 `Any` represented as `ClassType(Any)` outside pure type position
**Where**: to be pinpointed post-clone by grepping `mk_class_type` + `Any` in `crates/pyrefly_types/src/{heap,stdlib}.rs` (research could not pin exact line from tree alone).
**Fix**: ensure `Type::Any(AnyStyle)` is always constructed via its own variant, never reified as a `ClassType` whose name string is `"Any"`. Add a debug-assert that `ClassType` construction rejects qname `builtins.Any` / `typing.Any`. Audit the stdlib bootstrap path in `stdlib.rs`/`heap.rs`.
**Risk**: low-medium once located.

### 4.4 TypeVar `_T` leak from `copy.deepcopy` in attrs converter
**Where**: `pyrefly/lib/alt/class/attrs.rs` (or the legacy attrs path) synthesizing `__init__` from field `converter=`. `copy.deepcopy` stub uses TypeVar `_T`; pyrefly fails to bind `_T` to the field type, leaking `_T` into the synthetic signature.
**Fix**: when synthesizing `__init__` from a converter callable, infer the converter's TypeVar bindings against the declared field type before splicing. Reuse the existing `solve.rs` substitution machinery: treat the field type as the argument type to the converter's first parameter, solve `_T := field_type`, then substitute into the return type.
**Risk**: medium. General fix (any TypeVar-bearing converter), not just `deepcopy`. Add conformance tests for `copy.deepcopy`, `json.loads`, `str` as converters.

### 4.5 `@overload` docstring vanishes on hover
**Where**: `pyrefly/lib/lsp/wasm/hover.rs` (consumes `Overload`) + `pyrefly/lib/alt/overload.rs` (solver).
**Root cause**: `overload.rs` does not thread the selected implementation's `Docstring` through to the hover provider.
**Fix**: `Overload` variant carries the chosen `Function` (which has a `Docstring`); hover.rs picks the selected overload's docstring, falls back to the `@overload`-decorated stub's docstring if the impl has none. Verify against pyright's behavior (pyright shows the matching overload's docstring).
**Risk**: low.

### 4.6 Dunder access in `__init_subclass__`
**Where**: `pyrefly/lib/binding/classdef.rs` (or the class-synthesis pass handling `__init_subclass__`).
**Fix**: `__init_subclass__` cls parameter is the subclass; `__name__`, `__qualname__`, `__type_params__` are valid attributes on it. Add these to the allowed-attribute set for the `cls` binding in `__init_subclass__` and `__class_getitem__`/`__init_subclass__` contexts.
**Risk**: low.

### 4.7 Match-case narrowing on tuples / None / call results
**Where**: `pyrefly/lib/binding/pattern.rs` (match-pattern binding) + `pyrefly/lib/alt/narrow.rs` (solver narrowing).
**Fix**: extend narrowing for `case (a, b):` against a subject of type `tuple[T, U] | None` to (a) narrow away `None` in the tuple arm, (b) bind `a`/`b` to component types, (c) handle `case func():` where the subject is a call result by narrowing on the call's return type. Reference pyright's narrowing rules (research report).
**Risk**: medium. Narrowing is the most subtle part of any type checker. Mitigation: port pyright's narrowing test suite cases.

### 4.8 Methods misread as properties on Unions of sibling subclasses
**Where**: `pyrefly/lib/alt/narrow.rs` + attribute resolution in `lib/alt/types/instance.rs`.
**Root cause**: when a Union contains two classes with a common parent, attribute lookup on the union picks the wrong member kind (property vs method) due to union-attribute resolution order.
**Fix**: union attribute resolution must intersect attribute kinds across all members; if one member has a method and another a property with the same name, that's a genuine ambiguity (error), but if all members agree on kind, use that kind. Add a regression test.
**Risk**: medium.

### 4.9 Python <3.10 `NoneType` panic + `dataclass_transform` detection
**Where**: `NoneType` panic in stdlib stubs under `--python-version 3.9`; `dataclass_transform` detection in `lib/alt/class/dataclass.rs`/`classdef.rs`.
**Fix (NoneType)**: ensure `NoneType` is present in the 3.9 bundled stubs or synthesized by the type engine regardless of stub availability. Add `NoneType` to the `Stdlib`/`Heap` bootstrap unconditionally.
**Fix (dataclass_transform)**: detect `typing_extensions.dataclass_transform` by behavior (it's a callable that returns a decorator), not by identity (`is`/`==` against `typing.dataclass_transform`). In 3.10 and older, `typing_extensions` defines its own `dataclass_transform` object; check by qualified name `typing_extensions.dataclass_transform` in addition to `typing.dataclass_transform`.
**Risk**: low-medium.
